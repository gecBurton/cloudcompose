# Revised Design: Environment Initialization + App Deployment

## Core Commands

```bash
# Step 1: Initialize environment (platform team, one-time)
composey init env --provider aws --name prod

# Step 2: Deploy apps (developers, many times)
composey up --env prod.yml
```

---

## Command: `composey init env`

### Purpose
Creates the shared infrastructure (VPC, ALB, NAT, etc.) that multiple apps will share.

### Usage

```bash
# Interactive (guided)
composey init env --provider aws --name prod

# Non-interactive (CI/CD)
composey init env \
  --provider aws \
  --name prod \
  --region us-east-1 \
  --vpc-cidr 10.0.0.0/16 \
  --output prod-infrastructure/
```

### What It Creates

```
prod-infrastructure/
├── main.tf.json          # Terraform for VPC, ALB, ECS Cluster
├── environment.yml       # Reference file for apps
└── terraform.tfstate     # State tracking
```

### Generated `environment.yml`

```yaml
# Generated by: composey init env --provider aws --name prod
# Used by: composey up --env prod.yml

target: aws
name: prod
region: us-east-1

# References to shared infrastructure (auto-populated)
vpc_id: ${aws_vpc.prod.id}
public_subnets:
  - ${aws_subnet.public_1.id}
  - ${aws_subnet.public_2.id}
private_subnets:
  - ${aws_subnet.private_1.id}
  - ${aws_subnet.private_2.id}

ecs_cluster_arn: ${aws_ecs_cluster.prod.arn}
alb_arn: ${aws_lb.prod.arn}
alb_listener_arn: ${aws_lb_listener.https.arn}
alb_security_group_id: ${aws_security_group.alb.id}

# Platform policies
retain_data_on_destroy: true
log_retention_days: 30
```

## Command: `composey up --env prod.yml`

### Purpose
Deploys an application to an existing environment.

### Usage

```bash
# Deploy with existing environment
composey up --env prod.yml

# Or shorter
composey up -e prod.yml
```

### What It Does

1. Reads `environment.yml` (the shared infra)
2. Reads `docker-compose.yml` (the app)
3. Generates app-specific Terraform
4. Deploys to the shared infrastructure

## Workflow Comparison

### Current (Complex)

```bash
# Developer needs to find/create all these manually
vim prod.yml  # Write 12 config fields with ARNs

composey up -f docker-compose.yml -e prod.yml -p my-app -o build/
cd build && terraform init && terraform apply
```

### Proposed (Simple)

```bash
# Platform team (one-time)
composey init env --provider aws --name prod
# Creates: prod-infrastructure/

# Developer (many times)
composey up --env prod-infrastructure/environment.yml
# Or simpler:
composey up -e prod
```

## Design Principles

### 1. Separate Concerns

| Command | Responsibility | Run By | Frequency |
|---------|---------------|--------|-----------|
| `init env` | Shared infrastructure | Platform team | Once per environment |
| `up` | Application deployment | Developers | Many times per app |

### 2. IaC Over Interactivity

```bash
# Prefer config files over prompts
composey init env --config env-config.yml

# env-config.yml
provider: aws
name: prod
region: us-east-1
vpc:
  cidr: 10.0.0.0/16
  azs: 3
alb:
  certificate_arn: arn:aws:acm:...
```

### 3. Sensible Defaults

```bash
# Minimal config needed
composey init env --provider aws --name prod

# Auto-detects:
# - Region from AWS_REGION or default to us-east-1
# - VPC CIDR from available ranges
# - Subnets automatically distributed
# - AZs automatically selected
```

### 4. Convention Over Configuration

```bash
# Default: Create VPC named "{env}-vpc"
composey init env --name prod
# Creates: vpc "prod-vpc"

# Override if needed
composey init env --name prod --vpc-name custom-vpc
```

## Example Workflows

### Small Team (One Environment)

```bash
# Setup (5 minutes)
composey init env --provider aws --name production

# Deploy app (2 minutes)
composey up --env production/environment.yml

# Deploy another app (2 minutes)
composey up --env production/environment.yml -f docker-compose-api.yml
```

### Large Organization (Multiple Environments)

```bash
# Platform team sets up environments
composey init env --provider aws --name prod --region us-east-1
composey init env --provider aws --name staging --region us-east-1
composey init env --provider gcp --name prod --region us-central1

# Store in version control
git add prod-infrastructure/ staging-infrastructure/

# Developers reference them
composey up --env prod/environment.yml
composey up --env staging/environment.yml
```

### CI/CD Pipeline

```yaml
# .github/workflows/deploy.yml
jobs:
  deploy:
    steps:
      - name: Setup Environment
        run: |
          # Environment already initialized
          # Just reference it
          echo "target: aws" > env.yml
          echo "name: prod" >> env.yml
          echo 'vpc_id: "${{ secrets.PROD_VPC_ID }}"' >> env.yml
          # ... other references
      
      - name: Deploy
        run: composey up --env env.yml
```

## Configuration Schema

### Environment Config (Generated)

```yaml
# Generated by init env, used by up

# Required
target: aws
name: prod

# Infrastructure references (auto-populated)
vpc_id: vpc-12345678
public_subnets: [subnet-1, subnet-2]
private_subnets: [subnet-3, subnet-4]
ecs_cluster_arn: arn:aws:ecs:us-east-1:123:cluster/prod
alb_arn: arn:aws:elasticloadbalancing:us-east-1:123:loadbalancer/app/prod

# Optional overrides
retain_data_on_destroy: true
log_retention_days: 30
```

### Environment Definition (Input)

```yaml
# Input to init env

provider: aws
name: prod
region: us-east-1

# VPC specification (optional, defaults provided)
vpc:
  cidr: 10.0.0.0/16
  enable_nat_gateway: true
  single_nat_gateway: false  # One per AZ for HA

# ALB specification (optional)
alb:
  enable_deletion_protection: true
  idle_timeout: 60
  
# ECS specification (optional)
ecs:
  container_insights: true

# Tags
tags:
  Environment: production
  Team: platform
```

## Benefits

### For Platform Teams

- **Standardized environments**: Consistent VPC, ALB, security
- **Version controlled**: Infrastructure as code
- **Reusable**: One environment, many apps
- **Secure**: Platform team controls security policies

### For Developers

- **Simple**: Just reference environment, no AWS expertise needed
- **Fast**: Deploy in 2 minutes, not 2 hours
- **Consistent**: Same environment for all apps
- **Focused**: Think about apps, not infrastructure

### For Organizations

- **Cost optimized**: Shared ALB, NAT Gateway across apps
- **Secure**: Centralized security policies
- **Scalable**: Easy to add new apps
- **Maintainable**: Clear separation of concerns
